# Правила участия в проекте

## Порядок работы
1. Создайте ветку от `main`.
2. Внесите изменения и сделайте коммиты.
3. Откройте Pull Request в `main` с описанием: что сделано, зачем, как проверить.
4. После ревью PR мержится, ветка удаляется.
Прямые коммиты в `main` запрещены.

## Именование веток
Латиницей, строчными, слова через дефис, с префиксом по типу задачи:
`feature/`, `fix/`, `docs/`, `refactor/`.
Пример: `feature/docker-compose`

## Оформление коммитов
Формат: `<тип>: <краткое описание>`, типы — `feat`, `fix`, `docs`, `refactor`, `test`, `chore`.
До 72 символов, без точки в конце, один коммит — одно логическое изменение.
Пример: `feat: add Dockerfile for web service`
